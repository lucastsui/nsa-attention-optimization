# NSA selected-attention optimization: final evidence

On one RTX 5090 **Laptop** GPU, moving the V load later in a pinned FLA kernel
improved selected-attention throughput by **22.1–31.5% over a 12-configuration
tuned original**, across nine target workloads in two fresh-process sessions.
Every comparison of round medians favored the candidate (7/7 in each workload,
session, and original-control comparison). This is a branch-level, warm-cache
forward result on synthetic activations, not a whole-model or generated-token rate.

![Measured throughput gain](figures/throughput.png)

## Measurements

BF16; 4,096/8,192/16,384 tokens; 64 query heads; four KV heads; D=128;
64-token blocks; up to 16 selected blocks. Three patterns: scattered, recent,
and indices generated by FLA's actual compression/top-k path. The latter still
uses synthetic Q/K/V. Times below are synchronized batch wall-time medians.

Seven rounds per session, three batches per arm per round, each targeting 100 ms.
Order rotates; session 2 reverses the initial order. Raw samples, CUDA-event
intervals, input hashes, tuning choices, resource counts, and GPU telemetry are
retained. Laptop clocks vary, so report sessions separately. The chart shows round
variation rather than implying the reported range is a universal performance bound.

The original initial study recorded 21–24% gains over native FLA on six seed-17
workloads, plus a 20.8% target confirmation. The new seed-29 sessions broaden the
baseline search and selection patterns; they do not erase those earlier results.

## Why the change helped here

K is used to calculate attention probabilities before V is needed. Loading V near
its use reduces how much intermediate data must remain live simultaneously. At
the profiled D128/block64 shape, shared memory fell from 36 to 22 KiB per block,
registers from 152 to 128 per thread, and the resident-block limit rose from two
to four. Both kernels had zero reported register spills.

![Resource comparison](figures/resources.png)

The unchanged eight-warp control raised occupancy but did not improve ordinary
timing. The useful outcome is less elapsed time; occupancy alone is not sufficient.
Nsight's cache-flushed, base-clock durations are diagnostic and are not the headline
throughput measurements. See [the initial experiment](EXPERIMENT_RESULTS.md) for
its negative results and detailed counters.

## Correctness and reliability

**166 numerical comparisons passed**: 85 original comparisons, 75 expanded
comparisons including the wider tuning control, and six checkpoint-shape checks.
These correspond to 52 distinct input configurations, with repeated providers
counted as comparisons. Maximum relative L2 error across these reports was
0.00241723, below the predeclared 0.01 limit. Every checked element also satisfied
`abs(error) <= 0.01 + 0.01 * abs(reference)`. Absolute error alone can exceed 0.01
while satisfying this combined tolerance.

Small cases check all query rows. Large cases check up to 24 deterministic rows plus
finiteness of all outputs. The CPU reference uses FP64 and independent dense masked
attention from the same quantized inputs. Three additional seeds cover K dimensions
64/96/128/256, V dimensions including 80 and 256, blocks 32/64/128, groups 16/32,
FP16/BF16, packed sequences, and sparse selections. Two analytic reference tests
also pass. This does not establish backward-gradient, separate-LSE, or exhaustive
large-tensor correctness.

**Sanitizer validation now passes.** After enabling NVIDIA's Windows GPU debugger
interface, Compute Sanitizer 2025.1 (CUDA 12.8) completed memcheck, racecheck,
synccheck, and initcheck with zero reported errors and exit code zero. Each tool
ran ten cases, including the full 8K target and FLA-generated selections; all 40
accompanying numerical rechecks passed. These repeats are separate from the 166
comparisons above. The unchanged candidate source hash was verified.

The first filtered initcheck attempt reported uninitialized host-copy inputs from
uninstrumented PyTorch reduction/gather kernels. A complete unfiltered run tracked
those producers and passed with API checking enabled. That diagnostic attempt is
retained. A valid-read control passed, and an intentionally invalid-read control
was correctly rejected, confirming instrumentation works. See
[sanitizer results and scope](SANITIZER_RESULTS.md).

## Model-shape screening and novelty

A compatible public research checkpoint exists: [zen-E/NSA-1B](https://huggingface.co/zen-E/NSA-1B).
Its head grouping fits, but its D64/block16 shape differs from the target. The
following checks use that shape and FLA-generated indices with random activations;
they do not run the checkpoint or its other attention branches.

| Synthetic checkpoint shape | Tuned original | Candidate | Throughput change |
| --- | ---: | ---: | ---: |
| N=2048, Hkv2/G16/D64/block16 | 0.076 ms | 0.131 ms | -42.34% |
| N=8192, Hkv2/G16/D64/block16 | 0.333 ms | 0.591 ms | -43.69% |

The candidate regresses on both checkpoint shapes. The tuned original selects one
warp, whereas this candidate fixes four warps. This is a negative transfer result
for the chosen configuration, not proof that every delayed-load configuration is
slower. Full-model integration is not justified as a speedup demonstration for this
candidate; keep the claim scoped to the measured D128/block64 workloads.

The established technique is also visible in [Triton's fused-attention tutorial](https://triton-lang.org/main/getting-started/tutorials/06-fused-attention.html).
This is an empirical systems-engineering contribution on a particular GPU/compiler,
not an invention of delayed value loading or a new attention mechanism. The current
integrated FLA package was inspected but not benchmarked. No fastest-implementation
claim is made. See [prior work and checkpoint assessment](PRIOR_WORK_AND_MODEL.md).
